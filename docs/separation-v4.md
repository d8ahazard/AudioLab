# AudioLab V4 separation

The default is now **`hybrid_cleaned`**, explicitly selected by the user after blind listening: V2 vocals, V4 instrumental, and residual-guided vocal cleanup capped at 3 dB with one mask shared across stereo channels. The cleanup won once and tied five times against plain V2 vocals; the original V4 instrumental won five times and tied once against V2. This is a user-selected default, not a claim that the original majority-win/full-song promotion criteria were completed. V1–V4 and public output filenames remain supported; the original three-model V4 stays experimental.

The hybrid runs six core models sequentially and retains Balanced quality by default. It uses fixed V2/V4 child recipes with no preset/fusion/residual overrides; ensemble size must be omitted or six. Both model sets/configs enter cache identity and manifest provenance. Downstream backing-vocal separation and cleanup run once, after the hybrid is formed. Existing explicitly saved profiles remain honored. Restart the app to load the new default; saved project settings may still select their previous profile.

Backing-vocal comparisons are generated by `scripts/compare_background_vocals.py` under `outputs/separation_v4_validation/background-comparison/`. They use the exact cached cleaned hybrid excerpts selected in listening, with the former BVE default as the control against BVE v2, Frazer–Becruily karaoke, and equal averaging of the latter two. After listening, the user selected **Frazer–Becruily BS-RoFormer Karaoke** (`backing_vocal_model=karaoke`) as the default for every profile. Explicit alternative selections remain supported. Final sample players and downloads are generated by `scripts/report_final_separation.py`, excluding the source used in background comparison #4. They retain the tested samples rather than silently replacing them with new inference.

## Runtime installation

All dependency manifests pin `audio-separator[gpu]==0.47.0`. The tested Windows runtime retains Torch 2.7.1+cu128 and selects ONNX Weekly 1.20.0.dev20251005, ONNX Runtime GPU 1.22.0, onnx2torch-py313 1.6.0, protobuf 4.25.8 and TensorBoardX 2.6.5. TensorBoardX's older generated protobuf code is incompatible with protobuf 4.

The unified installer stages these packages under the active environment's `audio_separator_runtime/` and activates them with `audiolab_separator_runtime.pth`. This gives each import namespace one selected owner without trying to overwrite DLLs held by a running app. Restart AudioLab after installation. Existing base distributions remain on disk for the running session; their metadata can still appear in package inventories. The installer probes the staged imports before activation. Removing the `.pth` restores base-package selection for future processes; it does not roll back source changes.

`normalize_separator_runtime(cpu_only=True)` selects the CPU ONNX runtime. CPU inference can also be requested per job with `cpu=True`, without changing process-wide environment variables. The original ONNX monkey patch is no longer used. CUDA provider options are instance-local. MDX models use waveform inversion because 0.47.0's spectral-inversion path has a channel/time shape error; a failed old V3 comparison is preserved in the local validation report.

RVC ONNX export now validates its exported graph directly rather than requiring `onnxsim`, which installs the competing stable `onnx` distribution. This removes automatic graph simplification but retains export and ONNX validation. The environment had pre-existing dependency conflicts in unrelated TTS/training packages; see the before/after inventories rather than treating `pip check` as a clean installation bill of health.

## Recipe and controls

Initial core trio: Unwa Vocals Resurrection, Unwa Big Beta 7, and Becruily Instrumental. All three run on the original mix; vocal and instrumental fusion are independent. The default is equal-weight waveform averaging with no residual fill, gain increase or per-stem normalization. Float WAV preserves the model outputs' gain, including peaks above digital full scale.

Beta 7 and the Deux comparison model have pinned author revisions and SHA-256-verified checkpoints/configs. Deux's CC-BY-NC-4.0 license is recorded in metadata. Other models use AudioSeparator's registry, and their local checkpoint/config hashes are recorded in manifests and cache identities.

| Setting | Behavior |
| --- | --- |
| `separation_quality=fast` | Profile's full model set; MDXC overlap count 2 |
| `balanced` (default) | Profile's full model set; author YAML overlap defaults |
| `maximum` | Profile's full model set; at least 8 overlaps, preserving higher author defaults |
| `smart_stems=auto` | Conservative for cleaned hybrid/V4; off for V1–V3 |
| `smart_stems=off/conservative` | Explicit filtering override |
| `backing_vocal_model=bve/bve_v2/karaoke` | Optional backing-vocal specialist |
| `instrument_model=demucs/roformer_sw` | Optional individual-instrument specialist |
| `instrument_input=mix/instrumental` | Input to the instrument specialist |
| `vocal_fusion` / `instrumental_fusion` | Advanced independent fusion selection |

The initial trio's YAMLs use overlap 2, so Fast and Balanced currently have the same core inference effort. Maximum is the more expensive option. Author chunk sizes are retained, subject to upstream short-input padding/segment handling. Batch size starts at 1. OOM errors are explicit; no silent quality downgrade occurs.

V4 presets retain three core models: instrumental/karaoke requests select minimum-magnitude instrumental fusion, acappella/podcast requests select minimum-magnitude vocal fusion, and remix uses averaging. An explicit fusion setting takes precedence. These are experimental objectives, not claims of universally better output. Legacy presets retain their historical model recipes.

Backing-vocal layers stop when the remainder is confidently empty/noise-only. Full vocals, lead vocals and the backing aggregate remain available. Each enabled cleanup runs once on each requested final stem. `Main Vocals`, `All Vocals`, and `All` are honored independently for reverb, echo/delay, crowd and noise. Instrument children and drum components use their actual output names, including a combined cymbals stem where that is what the model predicts.

## Smart Stems and caching

Smart Stems examines channel-preserving short-window energy, level relative to the parent, spectral flatness and temporal variation before output normalization. It hides digital silence or very faint stationary broadband noise. Tonal frames, sparse onsets, short notes and uncertain results are retained. This is conservative signal analysis, not semantic sound recognition; inspect retained noise or recover hidden results when needed.

Hidden float WAVs live in `.hidden_stems/`, with reasons, measurements and hashes in `separation_manifest.json`. Normal outputs, project enumeration and downstream processing exclude them. In Process, select an Existing Project, then use **Smart Stems recovery → Show hidden stems → Restore selected stem**. Restore validates the hash, moves the original file back and updates the cache without inference. Intermediate cleanup does not delete this archive.

The manifest describes aggregate/child relationships. Merge prefers instrumental over its instrument children, drums over drum children, and lead/backing vocals over full vocals when both are passed. To mix individual instruments, select the children without the aggregate. Restoring or retaining an aggregate does not mean it should be summed with its children.

Cache identity covers source content, package version, pipeline revision, resolved recipe, custom-model definitions, options, and local model/config hashes. Visible and hidden outputs are checked before cache reuse. An explicitly empty separation result does not fall back to processing the original mix.

## Local validation and listening

Artifacts are under `outputs/separation_v4_validation/`: `REPORT.md`, `listening.html`, original baseline snapshots, corpus offsets, cached predictions, nine three-model recipes with five fusion algorithms, specialist comparisons, full-song candidate stems and operational-test results. Existing user project outputs are not used as scratch space.

The six-project corpus includes both September 23 recordings, both recent “The Day That Never Comes” projects, `lucifer_full`, and “Lorde – Royals US Version.” Excerpts are fixed 8-second sections at 15%, 50%, and ten seconds before the end. They are reproducible coverage samples, not manually annotated vocal/chorus boundaries. The source songs lack reference stems: do not assign them reference SDR scores.

Run `scripts/benchmark_separation_v4.py --help` for preparation, baseline, candidate, fusion, specialist and full-song stages. `scripts/report_separation_v4.py` builds the listening page and report. The baseline command requires the preserved old pipeline files; run 0.41.1 baselines in their preserved environment before upgrading. Benchmark caches are local artifacts, not a replacement for the application's content-validated cache.

The original blind listening page compares the initial candidate to 0.41.1/V2 results, with downward RMS matching applied only to audition copies. It also exposes every candidate recipe at original gain. The original V4 failed its majority-win/no-severe-regression gate. Subsequent hybrid listening favored the cleaned hybrid narrowly; the user explicitly selected it as the new default. Historical reports preserve the decisions at each round; this does not imply completion of full-song/backing-vocal review.

Automated coverage: `testing/unit/modules/test_separator_v4.py` and `testing/smoke_separator_v4.py`. The latter performs real inference in the validation folder and is resumable. Runtime/VRAM logs are observations, not controlled speed rankings, because some evaluation jobs ran concurrently.
